# WinCalendar 开发说明

[返回产品介绍](../README.md)

## 构建与检查

主程序使用 C#、WPF 和 .NET 8，日历解析使用 Ical.Net。以下命令均在工程根目录运行，需要 .NET 8 SDK。

```powershell
dotnet build WinCalendar.csproj --disable-build-servers -p:UseSharedCompilation=false
dotnet run --project Checks/Checks.csproj
dotnet publish WinCalendar.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=false -o publish/win-x64
```

独立发布包使用 .NET 8.0.30，用户无需另装运行时。普通 `dotnet publish` 不代替下方发行脚本：在线更新还需要文件清单和校验文件。

### 诊断与界面预览

```powershell
dotnet bin/Debug/net8.0-windows/WinCalendar.dll --probe-clock clock-probe.txt
dotnet bin/Debug/net8.0-windows/WinCalendar.dll --integration-check integration-results.txt
```

诊断不读取私人订阅链接；集成检查使用隔离数据。时间入口诊断输出系统和任务栏结构，不输出控件名称或订阅链接。

`--preview` 为界面调试模式，暂停失焦关闭并显示任务栏图标；日常使用不要附加此参数。`--background` 用于后台自启动。

跨版本回归需要 PowerShell 7，可用 `-NuGetSource` 指定本地包源：

```powershell
pwsh -File Checks/CrossVersion.ps1
```

脚本从历史提交构建 1.0.0、1.0.1，在隔离源码副本中使用合成数据和测试启动入口，保留实际更新逻辑，检查升级、确认延迟、失败恢复、完成超时及再次启动。本地 ZIP 检查不代替线上下载与实机任务栏验收。历史结果见[验证记录](../QA.md)。

## 打包与发布

在 PowerShell 7 中运行，必要时附加 `-NuGetSource`：

```powershell
pwsh -File Scripts/build-release.ps1
```

脚本执行检查，从干净暂存目录生成包含运行时的 `publish/releases/WinCalendar-{版本}-win-x64.zip`、`release-files.json` 和 ZIP 的 `SHA256SUMS.txt`。安装 EXE 的构建方式见[安装包说明](../Installer/README.md)。

正式发布使用 `v主版本.次版本.修订号` 标签，与工程版本一致。在同一 GitHub Release 上传安装 EXE、更新 ZIP，以及包含两者摘要的合并 `SHA256SUMS.txt`。两个输出目录中的校验文件分别对应各自产物，发布前需要合并，不要用其中一份覆盖另一份。

更新来源固定为 `houjie1212/WinCalendar` 的最新正式 Release，忽略预发布；只有更高版本才会触发更新。同版本构建需要安装包覆盖安装。发布脚本不会上传文件或创建标签。

当前打包脚本复制 README 和许可证，不复制 `docs/`；发行包内 README 的相对图片及开发文档需到仓库查看。本次文档整理不改变打包内容。

## 订阅与日期规则

- 支持多个 HTTPS／Webcal 地址，Webcal 转为 HTTPS；默认每 30 分钟刷新。编辑订阅后仍需保存设置页。“立即刷新”先保存设置再下载。
- 常用订阅提供中国、日本、美国假日。中国支持放假及补班、仅放假、仅补班；日本支持含国家名称、隐藏国家名称、包含非公共假日；美国还提供仅联邦假日。每个订阅保存一个地址，不自动添加任何订阅。
- 点击已添加的同组预置时编辑已有订阅，保留用户字段；保存时阻止重复地址。主动选择“自定义地址”会清空地址栏；重新打开或切换语言不会清空。
- 中国休班识别兼容 [ShuYZ 日历](https://raw.githubusercontent.com/lanceliao/china-holiday-calender/master/holidayCal.ics)，且订阅类型必须为“中国节假日”。仅识别完整标题“节日名 假期 第N天/共N天”和“节日名 补班 第N天/共N天”，不根据描述猜测。未知事件仍作为普通日程显示。
- 假日标记按源日历日期生成；定时详情使用系统本地时区。全天结束日期为排他边界。多个来源休班冲突时隐藏角标并提示；名称按订阅顺序显示首个，其余保留在提示和详情中。
- 所有启用订阅的日程参与背景着色，同一天按订阅顺序显示前 3 个来源，同源多事件不重复占位；同色来源仍各占一份。完整来源和事件保留在提示及详情中。
- 月历范围为 1901—2100。加载范围包含上月、当前月、下月各自的完整 42 格网格，含跨月日期；解析范围上限为 112 天。翻月使用已有数据，再从本地缓存补齐，不额外下载。快速连续翻月最终补齐最新显示月份。
- 切换月份保留选中日期；点击“今天”才更新选择。跨过零点后，定时检查刷新今天标识，不自动切换选中日期或月份。
- 农历默认关闭，使用 .NET ChineseLunisolarCalendar，正确区分闰月，超出支持范围留空。初一显示月份；假日名称优先，农历保留在提示中。不恢复内置节日或调休推算。
- 界面跟随 Windows 显示语言，支持简中、繁中、英文和日文，未支持语言回退英文。日期格式和默认周起始日跟随区域设置，周起始日可单独设置。已知节日名称可翻译，订阅原始标题、地点和描述不翻译，已保存的订阅名称不自动更名。

### 下载限制与本地数据

订阅下载仅支持公网直连，禁用系统代理与 Cookie。初始连接及重定向均检查 DNS 结果，拒绝本机、私网和特殊用途地址，包括混合公网／内网结果；直接连接已批准的 IP，保留正常 TLS 证书校验。此策略不改变 GitHub 更新下载。

下载限制为 5 MiB、25 秒、最多 5 次 HTTPS 重定向。解析在独立进程中执行，限制为 10 秒、256 MiB 和 10,000 条展开事件；失败或超限保留有效缓存。

数据位于 `%LOCALAPPDATA%\WinCalendar`：`settings.json` 保存配置，`订阅标识.ics` 保存日程缓存。不再读取旧 `holiday-年份.json`，也不主动删除这些历史文件。

订阅地址通过 Windows DPAPI CurrentUser 加密，仅在配置读写边界转换。旧明文配置原子迁移，不生成明文备份；失败时保留原文件并提示。单条解密失败保留密文、属性和缓存，暂停该条下载，重新填写地址后恢复。跨用户或电脑复制配置可能无法解密。

日程缓存仍为明文，外部历史备份不会清理。DPAPI 不能防御已控制同一 Windows 账户的程序，不能据此认为整个数据目录可公开分享。

## 更新安全与恢复

更新仅手动触发，要求完整发行目录（包含 `release-files.json`）、可写权限和足够空间；不自动提权。提升权限运行时禁止更新和恢复。未保存的设置须先保存。

下载仅接受固定仓库的 HTTPS 发行资产及允许的 GitHub 跳转，校验 SHA-256、包内版本和文件清单，并限制大小、解压路径及链接条目。只替换清单管理的文件，保留额外文件及用户数据，自启动路径保持不变。发行包未签名，摘要只用于完整性与一致性检查，不是可信签名。

更新事务保存在 `%LOCALAPPDATA%\WinCalendar\Updates`。恢复记录绑定当前程序目录及进程身份，核验 PID、启动时间、实际路径、文件大小和摘要；未经校验不执行替换、恢复或进程操作。这不能防御已完全控制当前账户的恶意程序。

1.0.2 兼容 1.0.0 缺少格式字段的记录，仅在更新启动时，经目标目录、阶段、工作进程和当前子进程验证后发送确认，不用旧记录执行文件操作。启动期间暂缓设置保存、订阅刷新和配置迁移，等待工作进程提交完成后开放；确认失败不会提前改写配置。

程序启动会检查可恢复的新格式事务，使用当前程序文件创建恢复进程，不直接执行历史工作程序。旧格式已完成或已恢复的合法记录被忽略；旧格式未完成、未知格式或校验失败的记录保留并提示修复。

**恢复失败或主程序无法启动时，使用新版安装包覆盖安装。不要手动运行历史 `worker` 中的程序，也不要删除未完成事务的记录和备份。** `--apply-update` 和 `--recover-update` 是内部工作进程入口，不是通用修复命令。成功事务的目录可在退出应用后手动清理。

卸载规则见[安装包说明](../Installer/README.md)：交互卸载默认删除数据，可勾选保留；静默卸载保留数据。取消卸载不删除数据，无法安全删除的目录或文件保留并提示。

## 兼容与验证

兼容目标为 Windows 11 x64，安装最低构建 22000；不代表所有版本均已实测。此前 25H2 已由用户实测，1.0.1 的任务栏识别改动及其他版本仍需对应实机验证，具体记录见 [QA.md](../QA.md)。

时间入口使用 UI Automation 和鼠标钩子，按实际控件结构识别，并提供原生时钟子窗口回退；不注入 Explorer，不先弹出原生面板再隐藏，不按版本号选择识别路径。Windows 更新仍可能改变任务栏结构。

实机验收包括：时间区域点击开关、无原生面板闪现、外部点击和 Esc、通知铃铛与 Win+N、退出恢复、Explorer 重启、多屏、DPI、自动隐藏任务栏及系统语言变化。编译和自动检查通过不能代替这些项目。
